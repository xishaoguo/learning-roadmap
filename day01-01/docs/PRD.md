| 项目 | 内容 |

## 2. 产品背景

租房用户通常需要在大量房源中快速完成筛选、比较、收藏和联系。HomeSeek 面向年轻职场人士与学生，以清晰、可信、低认知负担的移动端体验，提供房源发现到联系房东的核心链路。

当前版本用于验证视觉方向、信息架构和主要交互，房源及用户数据为前端演示数据，尚未接入真实业务后端。

## 3. 产品目标

1. 让用户在移动端快速浏览和筛选房源。
2. 通过图片、价格、位置和关键属性帮助用户完成初步判断。
3. 支持收藏、查看详情及联系房东的完整演示链路。
4. 保持与 Stitch 原型一致的可靠蓝、柔和极简视觉风格。
5. 提供可部署、可测试、可继续接入后端的 React 工程基础。

## 4. 目标用户

### 4.1 年轻职场人士

- 关注通勤位置、居住品质与月租预算。
- 偏好快速筛选并保存候选房源。
- 需要随时通过手机联系房东。

### 4.2 学生与初次租房用户

- 关注价格、房型和基本配套。
- 需要信息层级清楚、操作路径简单。
- 更依赖可信的图片与位置描述。

## 5. 信息架构

| 一级入口 | 页面职责 |
| --- | --- |
| Explore | 搜索、分类筛选和浏览房源 |
| Saved | 查看、筛选及取消收藏房源 |
| Messages | 展示房东回复和系统通知的空状态入口 |
| Profile | 用户资料、收藏及足迹统计、业务菜单 |
| 房源详情 | 展示图片、价格、配套、介绍、位置及联系操作 |

## 6. 功能需求

### FR-01 探索房源

- 默认展示 3 套演示房源。
- 每张房源卡展示图片、标题、价格、区域、卧室、浴室和面积。
- 首套房源可进入房源详情页。
- 卡片收藏按钮可切换收藏状态，且不触发详情跳转。

验收标准：页面首屏显示品牌、搜索框、分类标签和房源卡；点击首套房源可进入详情。

### FR-02 搜索与分类筛选

- 用户可根据城市、区域或房源标题输入关键词。
- 支持“全部、公寓、住宅、单间、阁楼”分类筛选。
- 关键词和分类条件同时生效。
- 无匹配项时展示明确的空状态。

验收标准：选择“住宅”后仅显示住宅；输入“深圳”后仅显示深圳房源。

### FR-03 收藏管理

- 房源卡支持收藏与取消收藏。
- Saved 页面默认展示演示收藏数据。
- 支持“全部房源、公寓、合租、整租”筛选。
- 收藏为空时展示引导性空状态。

验收标准：取消收藏后对应卡片立即从当前收藏列表移除。

### FR-04 房源详情

- 展示房源主图、图集序号、标题、评分、区域和价格。
- 展示 WiFi、厨房、空调和停车位等配套。
- 展示房源介绍、位置预览和详细地址。
- 支持返回、分享占位、收藏和立即联系。

验收标准：详情页固定底栏始终可见；收藏状态与探索页保持一致。

### FR-05 联系房东

- 点击“立即联系”打开底部操作面板。
- 面板包含手机号输入框和发送按钮。
- 提交后关闭面板并显示成功提示。

当前限制：本版本仅做前端反馈，不向服务端发送数据。

### FR-06 消息中心

- 展示无新消息状态。
- 说明房东回复和系统通知将在此出现。

### FR-07 个人中心

- 展示用户头像、认证标识、昵称、身份和加入时间。
- 展示收藏数及足迹数。
- 展示我的预约、租约管理、支付记录、设置和帮助中心入口。
- 未实现的入口点击后给出“即将开放”反馈。
- 退出登录按钮提供操作反馈。

### FR-08 底部导航

- 提供 Explore、Saved、Messages、Profile 四个一级入口。
- 当前入口有明确的颜色和图标状态。
- 切换页面后滚动位置回到顶部。

## 7. 视觉与交互规范

- 主色：可靠蓝 `#0066FF`，深主色 `#0050CB`。
- 背景：冷白 `#F8F9FF`；卡片背景为纯白。
- 字体：优先使用 Inter，中文回退至系统无衬线字体。
- 卡片圆角 16px，按钮及输入框圆角 10–13px。
- 页面最大宽度 430px；桌面访问时以手机容器居中展示。
- 底部导航和详情操作栏固定，兼容安全区域。
- 关键按钮需提供点击反馈；浮层可通过关闭按钮或点击遮罩关闭。

## 8. 非功能需求

### NFR-01 兼容性

- 支持近两个主要版本的 Chrome、Safari 和移动端系统浏览器。
- 最小布局宽度 320px，基准验证宽度 390px。

### NFR-02 性能

- 生产构建采用 Vite 资源哈希与静态缓存。
- 首屏图片使用本地静态资源，避免依赖 Stitch 外链。
- 静态资源由 Nginx 设置 7 天强缓存。

### NFR-03 可用性

- 图片包含替代文本。
- 输入框具有可识别的标签或占位提示。
- 核心操作可通过语义化按钮访问。

### NFR-04 安全与部署

- 仅通过 HTTPS 对外提供服务，HTTP 自动跳转 HTTPS。
- TLS 证书使用 Let's Encrypt，并启用自动续期。
- EC2 安全组需允许公网入站 TCP 80 和 443。
- Nginx 使用 SPA fallback，前端路由刷新时返回 `index.html`。

## 9. 数据模型（当前前端演示）

房源字段包括：`id`、`image`、`title`、`price`、`location`、`beds`、`baths`、`area`、`type`、`badge`。收藏状态在 React 内存状态中维护，刷新页面后恢复默认演示状态。

## 10. 数据埋点建议

后续接入分析平台时建议采集：

- `property_impression`：房源卡曝光。
- `property_click`：进入房源详情。
- `search_submit`：搜索词及结果数。
- `filter_change`：筛选类型及取值。
- `favorite_toggle`：收藏或取消收藏。
- `contact_submit`：联系请求提交。
- `nav_switch`：一级导航切换。

## 11. 本期范围外

- 真实账号注册、登录和退出。
- 服务端房源搜索、收藏同步与消息推送。
- 在线支付、合同签署与预约管理。
- 地图 SDK、定位和路线规划。
- 图片上传、分享接口和房东即时通信。

3. 接入地图及真实房源位置。
4. 增加图片懒加载、骨架屏和错误重试。
5. 完善消息、预约、租约及支付业务闭环。
